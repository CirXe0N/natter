The Consumers screen answers "is anything falling behind?". It lists every consumer of every stream, most lag first, and it's where you create and manage them.

The list

Each row shows the consumer and its stream, its filter subjects, ack policy, pending messages (the lag) with a bar, messages awaiting ack, redeliveries, waiting pulls and when it was last active. Badges mark paused, ephemeral and push consumers.

  • Filter by consumer, stream or subject.
  • Show Natter's browsing consumers includes the short-lived consumers Natter's own Message browser uses. They're hidden by default and always labelled.

A stream's Consumers tab shows the same table for that stream only.

A consumer's page

Open a consumer to see its pending, ack pending, redelivered and waiting counts, delivered and ack-floor sequences, when it was created and last active, and its full configuration. From here you can:

  • Pause it for 5 minutes, an hour or a day, and Resume it.
  • Edit it.
  • Delete it, after typing its name. It forgets its position, and every client using it loses it.

Create a consumer

Choose New consumer on the Consumers screen, pick the stream, and fill in what you need. Defaults match nats consumer add --defaults: durable, pull, explicit ack, from the first message.

SectionOptions
ConsumerName, durable or ephemeral, description, metadata (key=value lines).
DeliveryPull or push, filter subjects, where to start (first, new, last, last per subject, a sequence or a time), replay instantly or at original timing, headers only, sample frequency.
AcknowledgementAck policy (explicit, all, none), ack wait, max deliveries, backoff delays, max ack pending.
Pull optionsMax waiting pulls, max batch, max expires, max bytes per pull, priority groups (overflow, pinned client, prioritized) and the pinned TTL.
Push optionsDeliver subject, deliver group, idle heartbeat, flow control, rate limit.
StorageReplicas (empty inherits the stream's), inactive threshold, memory storage.

Only the options for the type you picked are shown. The JSON view shows exactly what Natter will send. A name that's already taken is refused, so creating never silently changes an existing consumer.

Edit a consumer

Some settings can't change after a consumer exists. The form marks them fixed after create: type, where it starts, ack and replay policy, idle heartbeat, flow control, max waiting pulls and memory storage. Everything else can change.

A Context is one NATS deployment's server URLs plus the credentials to reach it, the same idea as a nats CLI context. Exactly one Context is active at a time.

Where Contexts come from

Natter lists Contexts from two folders, side by side:

BadgeFolderWho else sees it
nats CLI Context~/.config/nats/contextThe nats CLI. Natter writes these files only when you ask it to.
Natter Context~/.config/natter/nats/contextOnly Natter. Its secret can live in the Vault.

If you set XDG_CONFIG_HOME, both folders move with it, on every system.

Switch Contexts

Use the Context switcher at the top of the sidebar or the Connect button on a card on the Contexts page. Natter remembers the active Context across restarts.

Create a Context

On the Contexts page choose New Context (or the dashed Add Context card). The form has four parts:

  • Connection: the name, a description, and the server URLs (several separated by commas).
  • Authentication: the kind of secret (none, password, token, creds file or NKey seed), where it is stored, and the user if there is one.
  • Natter settings: the Monitoring URL and Read-only mode.
  • Save in: Natter's folder, or the nats CLI folder so nats can use it too.

Where a secret is stored

Stored inWhat the Context file holds
VaultA reference to an entry in Natter's encrypted Vault. Only for Natter Contexts: the nats CLI can't read the Vault.
env://The name of an environment variable, such as env://NATS_PASSWORD.
1PasswordAn op://vault/item/field reference, read with the 1Password CLI.
nscAn nsc://operator/account/user reference, for creds files only.

References are resolved each time Natter connects, the same way the nats CLI resolves them. Natter never writes a secret into a file in plain text.

Edit or remove a Context

Each card has Edit and a remove button. Editing changes only the fields on the form; every other setting in the file (TLS, JetStream domain, inbox prefix…) is kept. The name can't be changed. When you edit the active Context, Natter reconnects with the new settings.

Your current secret is kept unless you choose Change secret. Replacing a secret that was in the Vault deletes the old one from the Vault.

Removing deletes the Context's file, and for a Natter Context its secret in the Vault too. You can't remove the Context you are connected to: switch to another one first.

Plaintext secrets

A natscli context that holds a password, token or key file in plain text gets a Plaintext secret badge: anyone who can read the file can use it. Choose Move into Vault on its card and Natter makes a Natter Context with the secret in the Vault. The original file stays as it is until you choose to delete it.

Server-wide data

Some screens (the server table on Overview, Connections, server health) need more than an ordinary user can see. A Context gets that in one of two ways:

  • System credentials: connect as a user in the system account. The card then shows a System credentials badge.
  • A Monitoring URL: the address of a server's HTTP monitoring port, such as http://127.0.0.1:8222. Natter uses it read-only.

Without either, the card says No system access, and those screens explain what's missing.

Capabilities

When Natter connects it checks what the connection can do, and the active card shows it: JetStream or No JetStream, System credentials, Monitoring URL (or Monitoring URL unreachable).

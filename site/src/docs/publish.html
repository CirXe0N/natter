Publish / Request sends a message to a subject, or sends a request and shows the reply. Save what you send as Example messages and send them again whenever you need.

Send a message

  1. Choose Publish or Request.
  2. Type the subject.
  3. Write the payload. If it's JSON, Natter checks it and can Prettify it. The size is shown against the server's max_payload, and a message that's too large is refused before it is sent.
  4. Add headers on the Headers tab if you need them.
  5. Press Publish or Send, or Ctrl/⌘ Enter.

The copy button next to the subject gives the matching nats pub or nats req command.

Requests and replies

A request shows its reply payload on the Response tab. The other outcomes read differently so you can tell them apart: no responders (nothing is subscribed to the subject), timed out after the timeout you set, or refused by the server. The History tab lists what you sent with the active Context while Natter is open in this tab.

Send many

On the Repeat tab, set a count to send the message that many times, publishes and requests alike, and the request timeout in milliseconds. The result says how many were sent.

Placeholders

A placeholder in the subject, a header value or the payload is replaced with a fresh value on every send. They use the same names as the nats CLI's templates, so the command Natter shows does the same.

PlaceholderBecomes
{{Count}}, {{Cnt}}The number of this message within the send: 1, 2, 3…
{{ID}}A unique ID (a NUID).
{{TimeStamp}}The time as RFC 3339, such as 2026-11-01T21:44:29Z.
{{Time}}The time of day, such as 9:44PM.
{{Unix}}, {{UnixNano}}Unix time in seconds, or nanoseconds.
{{Random 10 20}}A random string of letters and digits, 10 to 20 characters long.

The chips under the editor insert them at the cursor. Preview next send shows the payload exactly as it would go out, rendered by the server. A broken placeholder is flagged before you send.

Example messages

An Example message is a saved message (subject, headers, payload, and whether it's a publish or a request) that belongs to one Context. Open Examples to search and load them, grouped in folders.

  • Save keeps your changes; the save-as button makes a new one.
  • Copy to… copies examples to other Contexts, and Import from Context… brings them in. When a name already exists you choose to keep both, replace, or skip.
  • Recent examples appear as chips under the subject for one-click loading.

Examples are stored in Natter's own files, so you can save and edit them even in Read-only mode, though not send them.

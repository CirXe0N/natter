From an installed app to browsing your first stream. You need a NATS server to connect to; if you don't have one, the first step starts one locally.

1. Have a NATS server

Skip this if you already have one. Otherwise run a local server with JetStream and the monitoring port, for example with Docker:

docker run --rm -p 4222:4222 -p 8222:8222 nats:latest -js -m 8222

That gives you a client URL of nats://127.0.0.1:4222 and a monitoring URL of http://127.0.0.1:8222.

2. Open Natter

Start Natter from your app launcher, Start Menu or Applications folder. The desktop app opens in its own window, already signed in. Closing the window leaves Natter running in the tray; open it again from the tray icon or the launcher. More about the desktop app.

Using the command-line binary instead

Run natter open. It starts Natter and opens it in a Chrome, Edge, Brave or Chromium app window (your default browser if you have none), already signed in. Plain natter starts the server and prints a sign-in URL with a Launch token; open it once and your browser has a session. It listens on port 4280, or a free port if that one is taken. natter install-desktop adds a launcher entry that runs natter open.

3. Connect a Context

Open the Context switcher at the top of the sidebar (it says No Context until you pick one). Every context you made with nats context add is already in it: pick one to connect. Manage Contexts… at the bottom of the switcher opens the Contexts page.

To add a new one, choose New Context, give it a name and the server URL (nats://127.0.0.1:4222), and add a secret if the server needs one. More about Contexts.

4. Look around

  • Overview shows message rates, servers, the busiest streams and consumers with lag. Server-wide data needs system access or a Monitoring URL.
  • Streams lists your JetStream streams. Open one to see its config, consumers and messages.
  • Message browser lets you scroll and open the messages of any stream.
  • Press ⌘K (Ctrl K on Linux and Windows) to jump anywhere.

5. Lock production

Before you connect to anything that matters, turn on Read-only mode for that Context. Natter then refuses every change and every send while it is active.

Read-only mode is a per-Context lock. While a locked Context is active, Natter refuses every action that changes server state or data. Use it for anything that matters.

Turn it on

  • Click the Writable chip on the Context's card on the Contexts page; it turns into an amber Read-only chip.
  • Or use the same chip at the right of the top bar for the active Context.
  • Or set it in the Context's Natter settings when you create or edit it.

When it's on, the top bar turns amber, so you always know.

What it blocks

  • Creating, editing, purging and deleting streams.
  • Creating, editing, pausing, resuming and deleting consumers.
  • Deleting messages.
  • Publishing, and sending requests: Natter can't know what a service does with a request.
  • Kicking a connection.
  • Writing or deleting a nats CLI context file.

Blocked buttons stay visible and focusable, with the reason next to them, so nothing silently disappears.

What still works

  • Everything that only reads: Overview, Connections, streams, consumers, the Message browser and the Live tail.
  • Browsing messages: its short-lived consumers change nothing. See Browsing.
  • Saving and editing Example messages, which live in Natter's own files.
  • Managing Natter's own Contexts and the Vault.

The lock is enforced by Natter's server, not just hidden in the UI, so a request from anywhere else is refused too.

Common problems, and what to do about them.

macOS or Windows won't open Natter

The desktop app and the release binaries aren't signed by Apple or Microsoft yet. See First-run warnings.

The browser says "invalid Launch token"

This is for the command-line binary; the desktop app signs itself in. The token changes every time Natter starts. Use the URL from the run that's going now, or simply run natter open, which signs the window in for you.

The window closed but Natter is still running

That's the desktop app: closing the window hides it and keeps Natter in the tray. Click the tray icon or choose Open Natter to bring it back, or Quit Natter to stop it. Starting Natter again also shows the window that's already open.

The desktop window is blank or flickers on Linux

The app needs GTK 4 and WebKitGTK 6.0. On NVIDIA graphics it already turns off WebKitGTK's DMA-BUF renderer; if the window still doesn't draw, try starting it with WEBKIT_DISABLE_DMABUF_RENDERER=1 set yourself, and check that the AppImage can find the libraries.

Port 4280 is already in use

This is for the command-line binary; the desktop app uses a free port by itself. Natter picks a free port by itself and prints the URL it ended up on. To choose one, use -port. If Natter itself is already running, natter open finds it and opens another window on it.

"No system access" or empty server data

Overview's Health and Servers, and the Connections screen, need System credentials or a Monitoring URL on the Context. Add a Monitoring URL such as http://127.0.0.1:8222 when you edit the Context. See Server-wide data.

"Monitoring URL unreachable"

The server's monitoring port didn't answer at that address. Check the server was started with monitoring on (-m 8222), and that the port is reachable from where Natter runs.

"No JetStream"

JetStream didn't answer for this account: the server runs without it (-js), or the account has no JetStream. Streams, consumers and the Message browser need it.

A Context says the Vault is locked

Its secret is in the Vault and the Vault isn't unlocked. Type the passphrase on the Contexts page, or start Natter with -vault-key. If the Vault's key was only in the OS keyring and the keyring doesn't have it any more, the secrets in it can't be recovered: add a backup passphrase while you still can.

Could not connect

The Context's card shows the server's error, such as authorization violation. Check the URL and the secret by editing the Context. If the secret is a reference (env://, op://, nsc://), make sure it resolves in the environment Natter was started from.

A button is greyed out

The reason is written next to it. Usually the Context is in Read-only mode.

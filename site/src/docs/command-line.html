The command-line binary, natter, has a few commands. Run natter -h for this list. The desktop app starts from your launcher and ignores -bind, -port, -allowed-host, -dev and -redirect-file; it takes -vault-key.

Commands

CommandWhat it does
natterServes Natter and prints its sign-in URL with the Launch token.
natter openOpens Natter in a browser app window, starting it if it isn't running. The window is signed in; no token is printed.
natter install-desktopAdds the command-line binary to the app launcher. The entry runs natter open. The desktop app's installers add their own entry.
natter uninstall-desktopRemoves the launcher entry again.

Flags

FlagDefaultMeaning
-port4280Port to listen on. If it's taken, a free one is used.
-bind127.0.0.1Address to listen on.
-allowed-hostA hostname the browser may use besides localhost. Repeatable. Required when -bind isn't a loopback address.
-vault-keyAn age identity file that unlocks the Vault. Create one with age-keygen -pq -o natter.key.
-redirect-fileWith open: give the browser a file that redirects to the sign-in URL, so the token isn't on the browser's command line.
-devFor working on Natter itself: trust the Vite dev server at http://localhost:5173.

natter open takes the same flags as natter; they apply only when it has to start the server.

Files

Natter keeps its state in ~/.config/natter/ (or $XDG_CONFIG_HOME/natter/) on every system:

PathHolds
nats/context/*.jsonNatter Contexts.
contexts.jsonEach Context's Monitoring URL and Read-only setting.
active-contextWhich Context to reconnect to at startup.
examples.jsonExample messages.
vault.ageThe encrypted Vault.
vault.key.ageThe Vault key wrapped with your passphrase, if you set one.

natscli's own contexts stay in ~/.config/nats/context/.

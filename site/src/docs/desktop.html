The desktop app is Natter in a window of its own, with a tray icon and an installer. It runs the same server and the same UI as the command-line binary, so everything else in these docs applies to both.

Get it

Download the installer for your system from the Install page, open Natter from your app launcher, and connect a Context. There's no terminal and no token to copy.

How the window behaves

  • One window. Starting Natter again shows the window that's already open, instead of starting a second server.
  • Closing hides it. Natter keeps running in the tray, so live updates and your connection stay up. Click the tray icon, or choose Open Natter, to bring the window back.
  • Quit from the tray. Choose Quit Natter in the tray menu, or press ⌘Q on macOS.
  • Signed in for you. The app starts Natter's normal server on a free loopback port and opens the window with the Launch token already handed over. The token is never printed or put on a command line.

Updates

The macOS app, the Windows install and the Linux AppImage check for updates once a day, and when you choose Check for Updates… in the tray menu. They install only updates signed with Natter's release key. A deb or rpm install is updated by your package manager instead.

Linux notes

  • The app needs GTK 4 and WebKitGTK 6.0. The deb and rpm packages pull them in; the AppImage expects them on the system.
  • On NVIDIA graphics, WebKitGTK can't draw through the DMA-BUF path, so the app turns that renderer off (WEBKIT_DISABLE_DMABUF_RENDERER=1) before the window opens.
